# Paired comparison and component diagnostics

The comparison studio in `research.html` has two separate uses:

1. **Recorded evidence:** navigate saved scenarios/levels/seeds and baseline,
   strong-prompt, rejected historical p6 steering, and historical best-of-two arms.
   The original 0-4 scores, quotations and selection-bias caveats remain visible.
   Diagnostic donor rescue is displayed separately and is not labeled a model repair.
2. **Live matched replay:** after loading a research session, compare the unmodified
   canonical-metadata prompt with the request-local historical residual overlay.
   `fixed-prefix` compares one identical context; `conversation` replays the same
   player script but lets each arm retain its own NPC history. Both arms use fresh
   sequential prefill, full-logit CPU selection and identical per-turn seeds.
   Results are unjudged until a separate evaluator assesses them.

Run `npm run dev`, then open `http://localhost:5174/research.html`. Recorded
comparisons and statistical panels work without downloading weights or loading a
GPU session. Select **Study**, **Scenario / level / seed**, and the two arms; use
**Next turn** to replay the conversation. Hiding identities is a presentation aid,
not rigorous blinding: study labels and warnings can still identify a condition.

For live replay, choose a local pinned checkpoint or an already populated browser
cache and click **Load research session**, then the studio's live replay button.
No model download is initiated by the studio. Historical p6 remains an explicitly
rejected experimental condition, not a recommended deployment configuration.

Recorded data are generated by `node tools/research/build-comparison-demo.mjs`.
`node --experimental-strip-types research/mechanistic-repair/compare-evidence.mjs`
adds retrospective paired-quality and judge-consistency summaries. Neither command
runs the model or fabricates historical token probabilities that were not recorded.

## What is actually captured inside a layer

`capture` accepts `stages`:

- `layer-input`: incoming residual.
- `attention`: residual after attention/output projection, output SRQ and
  post-attention RMS norm; before the FFN.
- `mlp`: residual after the MLP/down projection, output SRQ and post-FFN norm;
  before PLE.
- `layer-output`: residual after PLE and layer-scalar multiplication.

Differences between adjacent boundaries measure normalized residual contributions,
not raw projection outputs. In particular, output-minus-MLP includes the layer
scalar as well as PLE. These captures do not by themselves identify a neuron, head
or native weight defect.

A `patch` can act at `attention`, `mlp`, or `layer-output`. Attention patches
recompute the next FFN input with the engine's f16/SRQ/f16 contract. MLP patches
feed the existing PLE computation. Final patches recompute the next-layer f32/SRQ
input. Zero/sham/activity/revert parity is checked on the actual checkpoint.

Historical residual steering is supported as request-local `overlays` only for
paired replay; it is never mixed with token-local diagnostic patches.

For example, the shared UI/CLI capture request is:

```json
{
  "id": "boundary-example",
  "op": "capture",
  "messages": [{"role": "user", "content": "Name three colors."}],
  "layers": [28, 32, 34],
  "stages": ["layer-input", "attention", "mlp", "layer-output"]
}
```

Omitted positions select the last prompt token. A patch uses `layer`, `stage`,
`tokenPosition` (if omitted, last prompt token), `mode`, `amount`, `vector` (1536 finite
numbers), and `sourceArtifactIds`, plus the receiver messages. Layer-input is
capture-only. Specify the actual shared assistant prefix when studying a later
decision; supplying a correct numeral instead would test a different hypothesis.

## Statistics and interpretation

The browser-compatible statistics module provides:

- paired fixed/broken/unchanged/unknown counts;
- equal-weight family effects, family bootstrap intervals and exact small-family
  sign-flip tests (subject to their symmetry assumptions);
- empirical multiple-random-control ranks, including their limited p-value
  resolution;
- Holm correction across the explicitly analyzed family of comparisons;
- judge duplicate and counterbalanced-order consistency.

All exploratory layer selection stays labeled exploratory. Six families, several
seeds, and thousands of tokens are still only six family clusters. Historical
best-of-two scores that reused their selection judges remain flagged as biased.
Ordinal CEFR categories are not continuous proficiency units.

The bounded new investigation is frozen in `component-protocol.json`. It measures
attention/MLP/PLE-plus-scalar contribution differences in two known discovery
failures, then tests multiple random directions and cross-case preservation only
if a candidate qualifies. No final set or weight repair is authorized by a
positive donor result alone.

## Reproducing the bounded investigation

Use Node with native TypeScript stripping support for the analysis scripts. Start
the research server on port 5190 with `GEMMA_RESEARCH_RUN=1` to disable HMR. Do not
modify runtime or tool sources within a run: the CLI verifies their fingerprint
before resuming. Use a new run ID and matched baselines if implementation changes.

```bash
GEMMA_RESEARCH_RUN=1 npm run dev -- --host 127.0.0.1 --port 5190
# In a second terminal:
node --experimental-strip-types tools/research/component-investigation.mjs prepare
RESEARCH_OUTPUT=research-results/component-localization npm run research:workbench -- \
  research-results/component-localization/baseline-requests.json components
node --experimental-strip-types tools/research/component-investigation.mjs screen
RESEARCH_OUTPUT=research-results/component-localization npm run research:workbench -- \
  research-results/component-localization/screen-requests.json components
node --experimental-strip-types tools/research/component-investigation.mjs summarize-screen
# Only when selected.json contains a qualifying candidate:
node --experimental-strip-types tools/research/component-investigation.mjs controls
RESEARCH_OUTPUT=research-results/component-localization npm run research:workbench -- \
  research-results/component-localization/control-requests.json components
node --experimental-strip-types tools/research/component-investigation.mjs summarize-controls
node research/mechanistic-repair/component-display.mjs
```

The CLI emits heartbeat/progress updates and checkpoints each job. Raw request
vectors, captures and event streams are retained locally but excluded from git.
Counts named `episodes` in its budget refer to evaluated continuations, including
score/capture jobs, not independent conversations or statistical samples.
